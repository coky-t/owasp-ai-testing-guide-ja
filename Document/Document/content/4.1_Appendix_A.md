## 4.1 付録 A: AI 脅威モデリングのアーキテクチャスコープとして SAIF を選択した理由 (Appendix A: Rationale for Selecting SAIF as the Architectural Scope for AI Threat Modeling)

AI 脅威モデリングのアーキテクチャスコープとして Google の SAIF を使用することを選択しました。これは、システムをデータ、モデル、アプリケーション、インフラストラクチャの層に明確に分解しており、構造化されたテストやセキュリティコントロールの配置を可能にします。

OWASP AI Security Matrix は脅威に焦点を当て、潜在的な攻撃対象領域を軸に構成されていますが、SAIF は防御とセキュアデザインを指向しています。いずれのフレームワークも高い補完性があります。SAIF は *何を保護するか* を定義するのに役立ち、OWASP は *何から保護するか* を定義するのに役立ちます。どちらも強固な基盤となり得ますが、実際には、両方に従うことで脅威のカバレッジとアーキテクチャ上のトレーサビリティを強化します。

ここでは OWASP AI Security Matrix で定義された AI アーキテクチャコンポーネントと Google の SAIF (Secure AI Framework) でのものを並べて比較します。これは、各フレームワークの共通の重点領域や独自要素を対応付けして、脅威モデリングやセキュリティテストの取り組みを整合するのに役立ちます。

| OWASP AI Security Matrix 対 Google SAIF: コンポーネント比較 |  |  |  |
| :---- | :---- | :---- | :---- |
| **コンポーネントカテゴリ** | **OWASP AI Security Matrix** | **Google SAIF アーキテクチャ** | **コメント** |
| データ | トレーニングデータ、入力データ、出力データ | データ (トレーニング、推論、変換、摂取にわたる) | どちらもトレーニングデータと入力データの両方を含みますが、SAIF はデータライフサイクルをより包括的に扱います |
| モデル | モデルアーキテクチャ、モデルパラメータ、モデルアーティファクト、モデル出力 | モデル (入力処理、使用、出力処理) | OWASP はモデルをアーティファクトとアーキテクチャに分けていますが、SAIF はランタイムとガードレールを重視しています |
| アプリケーション | プロンプトインタフェース、API、プラグイン、出力チャネル | アプリケーション、エージェント/プラグイン、ユーザー入出力 | 強い整合性: OWASP 「プロンプトインタフェース」 \= SAIF 「ユーザー入力」; プラグイン/コンポーネントも整合しています |
| インフラストラクチャ | モデルデプロイメント環境、CI/CD パイプライン、クラウドプラットフォーム/ホスティング | インフラストラクチャ、モデルサービング、モデルストレージ、モデル評価、トレーニングインフラ | OWASP と SAIF はいずれもデプロイメントとランタイム環境を重視していますが、SAIF はより詳細です |
| セキュリティガバナンス | 監視、ログ記録、アクセス制御 | ログ記録と監査、アクセス制御、アイデンティティと認証 | いずれのフレームワークも、テスト、トレーサビリティ、コントロールに不可欠なガバナンスコンポーネントを備えています |
| 外部依存関係 | サードパーティデータフィード、事前学習済みモデル、API/LLM | 外部ソース、プラグイン統合 | SAIF は信頼性境界を明示的に名前付けしていますが、OWASP はサードパーティモデルリスクを扱っています |
